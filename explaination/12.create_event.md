admin create event is achieved by frontend and backend

# Overview
Only an admin can create an event. The frontend sends the form data (and
uploads the image first), the backend checks the admin is allowed, validates
every field, then inserts one new document into the `events` collection.

# backend (api/admin/events/create.php)
It uses shared helpers from `api/admin/events/helpers.php` so create/update/
delete all validate the same way.

## Step 1: only POST, and only admin
`requireMethod('POST')` rejects non-POST requests.
`requireAdmin()` checks the session: must be logged in AND have role `admin`,
otherwise it stops with 401 (not logged in) or 403 (not admin).
```php
requireMethod('POST');
requireAdmin();
```
Inside helpers.php:
```php
function requireAdmin(): void
{
    if (!isset($_SESSION['user_id'])) {
        respond(401, ['success' => false, 'message' => 'Please log in first']);
    }
    if (($_SESSION['role'] ?? '') !== 'admin') {
        respond(403, ['success' => false, 'message' => 'Admin access required']);
    }
}
```

## Step 2: read and validate the fields
`readRequestData()` reads a JSON body (or a normal form post) into an array.
Then each field is pulled out with a helper that also validates it:
- `getRequiredString` -> field must not be empty, else respond 422.
- `getCapacity(..., true)` -> must be a positive integer (>= 1).
- `getOptionalString` -> may be empty (image_url).
- `getStatus(..., false)` -> if empty, default to `'Upcoming'`.
```php
$data = readRequestData();

$title = getRequiredString($data, 'title');
$category = getRequiredString($data, 'category');
$description = getRequiredString($data, 'description');
$eventDate = getRequiredString($data, 'event_date');
$eventTime = getRequiredString($data, 'event_time');
$location = getRequiredString($data, 'location');
$capacity = getCapacity($data, true);
$imageUrl = getOptionalString($data, 'image_url');
$status = getStatus($data, false) ?? 'Upcoming';
```

## Step 3: block "Deleted" as a starting status
"Deleted" is only for events that get removed later, not for new ones.
```php
if ($status === 'Deleted') {
    respond(422, ['success' => false, 'message' => 'New events cannot start as Deleted']);
}
```

## Step 4: build the event document and insert it
We make one MongoDB ObjectId and reuse its string form as `event_id`, so the
event can be looked up by either `_id` or `event_id`.
- `created_by` -> who made it, taken from the logged-in session `user_id`.
- `created_at` -> a MongoDB date (UTCDateTime) for the current time.
- `image_url` -> the Cloudinary URL from the upload step (see 8.image.md).
```php
$events = $db->selectCollection('events');
$eventObjectId = new MongoDB\BSON\ObjectId();
$eventId = (string) $eventObjectId;

$eventDocument = [
    '_id' => $eventObjectId,
    'event_id' => $eventId,
    'title' => $title,
    'category' => $category,
    'description' => $description,
    'event_date' => $eventDate,
    'event_time' => $eventTime,
    'location' => $location,
    'capacity' => $capacity,
    'image_url' => $imageUrl,
    'status' => $status,
    'created_by' => (string) $_SESSION['user_id'],
    'created_at' => new MongoDB\BSON\UTCDateTime(),
];

$events->insertOne($eventDocument);
```

## Step 5: respond with the created event
Status 201 means "created". `eventToArray` turns the document into a clean
API shape for the frontend.
```php
respond(201, [
    'success' => true,
    'message' => 'Event created successfully',
    'event' => eventToArray($eventDocument),
]);
```

# frontend (app.js)
The same form is used for create AND update. If it has an `event_id` it is an
update; if empty, it is a create.

## Step 1: read the form into a payload
```js
byId('admin-event-form')?.addEventListener('submit', async (event) => {
    event.preventDefault();
    const form = event.currentTarget;
    const imageFile = form.elements.image?.files?.[0] || null;
    const payload = {
        event_id: form.elements.event_id.value,   // empty => create
        title: form.elements.title.value,
        category: form.elements.category.value,
        description: form.elements.description.value,
        event_date: form.elements.event_date.value,
        event_time: form.elements.event_time.value,
        location: form.elements.location.value,
        capacity: form.elements.capacity.value,
        image_url: form.elements.image_url.value || '',
        status: form.elements.status.value,
    };
    const endpoint = payload.event_id ? '/admin/events/update.php' : '/admin/events/create.php';
```

## Step 2: upload image first, then send the event
If the admin picked an image file, upload it to Cloudinary first and put the
returned URL into `image_url`. Then POST the payload to the create endpoint.
```js
    try {
        if (imageFile) {
            payload.image_url = await uploadImage('event', imageFile);
        }

        await apiRequest(endpoint, {
            method: 'POST',
            body: JSON.stringify(payload),
        });
```

## Step 3: after success, jump to page 1 and refresh the list
For a NEW event we set pagination back to page 1 so the admin can see it,
reset the form, switch to the admin list tab, and re-render.
```js
        if (!payload.event_id) {
            setPagination('events', { page: 1 });
        }
        resetEventForm();
        setChecked('tab-admin-list');
        await renderEvents();
    } catch (error) {
        alert(error.message);
    }
});
```

# The full loop
```
admin fills the form and clicks submit
  -> frontend: if there is an image, upload to Cloudinary, get image_url
  -> frontend POSTs the payload to /admin/events/create.php
  -> backend: requireMethod('POST') + requireAdmin()
  -> backend: read + validate every field, block "Deleted" status
  -> backend: build event document, insertOne into events collection
  -> backend: respond 201 with the created event
  -> frontend: go to page 1, reset form, show admin list, renderEvents()
  -> the new event now shows in the list
```
